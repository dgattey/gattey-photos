# Distributing Gattey Photos (macOS auto-update)

Small family install: **ad-hoc** code signing (`-`) + `com.apple.security.cs.disable-library-validation` + Sparkle 2 EdDSA. No Apple Developer Program.

- Sparkle 2 validates and installs updates via the EdDSA signature (`SUPublicEDKey` in `Info.plist` + `sparkle:edSignature` in `appcast.xml`, generated by `scripts/generate-sparkle-key.sh`).
- Ad-hoc signing (`-`) with `com.apple.security.cs.disable-library-validation` works cleanly with macOS Gatekeeper's **Privacy & Security → Open Anyway** flow (whereas untrusted self-signed X.509 certificates get killed by `syspolicyd`/`amfid` on macOS Sequoia/Tahoe when quarantined).
- One-time per Mac: **Privacy & Security → Open Anyway** after a blocked launch; Sparkle updates after that.
- Each release is a GitHub Release (`v1.2.3`) on the merged commit with two assets: `Gattey-Photos-1.2.3.zip` and `appcast.xml`. Nothing is committed back to `main`, which a pull request ruleset protects. `https://photos.gattey.com/appcast.xml` is a temporary redirect to `https://github.com/dgattey/gattey-photos/releases/latest/download/appcast.xml`, and the download page and `/download/macos` read that same appcast, revalidated every minute.

## How it works

- App checks `https://photos.gattey.com/appcast.xml` (Sparkle 2, HTTPS only).
- `AppUpdaterModel` runs only when `SUFeedURL` and `SUPublicEDKey` are in the built app.
- Push to **`main`** with `macos/` (or packaging script) changes → `.github/workflows/release-macos.yml` builds and signs the app, then `gh release create` publishes the zip and `appcast.xml` on that commit. A commit that already has a `v*` tag is not released again.
- The site picks up the release within a minute, with no Vercel deploy.

PRs into `main` work the same way: merge → one release. No release branch, no release commit and no manual steps.

## Pick the version bump in the PR

GitHub fills new PR bodies from `.github/pull_request_template.md`, which ends with a **Release info** section:

```md
# Release info

- [ ] Major
- [ ] Minor
- [x] Patch
```

To ship a minor or major release, check **Minor** or **Major** before you merge. From 1.0.16, a patch release is 1.0.17, a minor release is 1.1.0, and a major release is 2.0.0. If more than one box is checked, Major wins over Minor and Minor wins over Patch. Only boxes under the `Release info` heading count, so a checked item under `What changed?` does not change the version.

`scripts/next-release-version.sh` computes the version. It reads the current version from `dist/previous-appcast.xml`, which `scripts/fetch-previous-appcast.sh` downloads from the latest GitHub release (falling back to the last `server/public/appcast.xml` in git history, from before releases moved to GitHub), then the live `appcast.xml`, then `macos/VERSION`, and falls back to `1.0.0`. It reads the release type from the first of these sources that is set:

1. `--release-type` or `GATTEY_RELEASE_TYPE`. A manual run of `release-macos.yml` sets this from the **release_type** input.
2. `--pr-body` or `GATTEY_PR_BODY`.
3. The merged PR for `GITHUB_SHA` from the GitHub API.
4. The commit message for `GITHUB_SHA` (or `HEAD`).

If the chosen source has no checked Major or Minor box under `Release info`, the release is a patch. To pin the current version in a test, pass `--current` or set `GATTEY_CURRENT_VERSION`. `server/lib/next-release-version.test.ts` covers each source.

## One-time setup

### EdDSA key

```bash
cd macos && swift build
./scripts/generate-sparkle-key.sh
```

Commit `macos/sparkle-public-key.txt`. Back up the private key (1Password, etc.):

```bash
macos/.build/artifacts/sparkle/Sparkle/bin/generate_keys -x sparkle_private.key
```

### GitHub secrets

From the repo root:

```bash
gh auth login   # once
./scripts/export-ci-secrets.sh
```

That pushes `SPARKLE_ED_PRIVATE_KEY_BASE64` with `gh secret set` on **this** repository. Do not paste base64 into the GitHub UI by hand.

| Secret | Purpose |
|--------|---------|
| `SPARKLE_ED_PRIVATE_KEY_BASE64` | EdDSA private key for signing release archives in `appcast.xml` |

Options: `--print-only`, `--dry-run`, `--skip-sparkle`, `--sparkle-key-file path`, `--repo owner/name`.

Leave Vercel **Production** Git deploys enabled (default). You do not need to change anything in the Vercel dashboard for this setup.

## First install (each family Mac, once)

1. Download from [photos.gattey.com](https://photos.gattey.com), unzip, drag **Gattey Photos** to Applications.
2. Try to open the app once (macOS will block it).
3. **System Settings → Privacy & Security → Open Anyway**, then open the app again.
4. **MDM-managed Macs (`DisableOverride = true`)**: Work MDM profiles (such as Kandji setting `DisableOverride = true` in `/Library/Managed Preferences/com.apple.systempolicy.managed.plist`) block **Open Anyway** from clearing `com.apple.quarantine` (`GKQuarantineResolver` fails with `Error -60005`). On those Macs, clear quarantine once in Terminal:

```bash
xattr -cr "/Applications/Gattey Photos.app"
```

After initial approval or `xattr -cr`, subsequent in-place **Sparkle** updates do not attach `com.apple.quarantine` and launch cleanly.

The release zip is ad-hoc signed with `com.apple.security.cs.disable-library-validation` (and stripped of build-machine Xcode toolchain `LC_RPATH` entries before signing) and verified by Sparkle 2 via EdDSA; macOS blocks unknown developers until you approve the app once via **Open Anyway** (or clear quarantine via `xattr -cr`).

## Notes

- Releases use `GatteyPhotos.local.entitlements` (`com.apple.security.network.client` + `com.apple.security.cs.disable-library-validation`, no `associated-domains`).
- `CFBundleVersion` is monotonic (`git rev-list --count` or the previous release's `appcast.xml` + 1).
- Every zip stays downloadable from its GitHub Release; none are committed to git.
